# 03 代码审查

目标：找到有依据、可行动的缺陷。

1. 明确审查对象是提交差异、模块还是整个仓库；读取足够上下文与调用方。
2. 优先检查正确性、数据损失、访问控制、并发、契约、错误处理及重要路径的测试。
3. 每个发现写明触发条件、实际后果、代码位置与建议。推测标注“待验证”，不能提升为已确认缺陷。
4. 严重程度依据影响与发生条件，不依据语言是否强烈。单纯风格偏好通常省略。
5. 无可确认问题是有效结果；说明检查范围和覆盖缺口。

若当前任务仅为审查，不自行改业务代码。可以运行已授权且与审查有关的验证；缺少环境时记录未验证。

输出：按影响排序的发现。每项结构为“问题 → 条件 → 后果 → 文件位置 → 证据 → 修复建议”。同一助手对自己修改的检查标注为自查。
