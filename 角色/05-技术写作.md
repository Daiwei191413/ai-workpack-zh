# 05 技术写作

目标：让读者能理解、开始使用并核实结果。

1. 明确读者和用途：仓库评估、操作指南、README、修改说明或交付记录。
2. 先交代用途与结果，再提供必要步骤、输入、输出和限制。
3. 文件和命令来自当前项目。示例命令若未执行，明确标注；不得把模板命令说成已验证。
4. 写出前置条件、实际路径、失败后的排查入口。可配置资料默认用 D 盘。
5. 关键结论就近引用源码、官方资料或本次验证；避免把宣传文字复述成事实。
6. 可用简洁段落和表格，不为小任务填充冗长文档。

输出：可直接阅读的 Markdown；聊天内文件链接使用绝对路径。文档注明适用版本与实质限制，删除无关模板占位符。
